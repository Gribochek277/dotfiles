message:
fix(nvim): run pi_name protocol handling in the main loop (E5560)
libuv callbacks are a 'fast event context': vim.notify (default handler ->
nvim_echo), the :PiLog buffer update and lualine.refresh all raise
E5560 there. handle_line() did all three, so connecting to an agent
failed with:

  E5560: nvim_echo must not be called in a fast event context
  pi_name.lua:56 in handle_line

Schedule every libuv entry point instead:
- read_loop returns a vim.schedule_wrap'ed callback (chunk order kept)
- the connect callback and the spawn poll timer are scheduled too

pi_agent/pi_models already scheduled their vim.system callbacks, so only
pi_name was affected. Covered by a regression test that runs the whole
connect/prompt/abort flow with the real vim.notify and asserts v:errmsg
stays empty (it reproduces the exact traceback on the pre-fix version).
